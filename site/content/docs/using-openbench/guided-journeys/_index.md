This guide uses the seeded **Thermal insulation comparison** to show how OpenBench records a study.
The values are examples, not recommended scientific protocols. OpenBench helps preserve evidence and
decisions; it does not certify a method, approve a claim, or replace scientific judgement.

## Before starting: understand the record chain

OpenBench keeps related concepts separate because they answer different questions:

| Record | Question it answers |
|---|---|
| Project | Which investigations belong together? |
| Experiment | What question, design, and intended use are being investigated? |
| Procedure revision | What written procedure was available for an execution? |
| Specimen | Which physical subject or sample received a condition? |
| Run | When and how was the procedure executed? |
| Measurement | What value was observed, how, and with what quality context? |
| Analysis snapshot | Which data revision and settings produced a calculation? |
| Conclusion | What did the researcher infer, with which limitations? |
| Scientific review | Who reviewed a defined scope against the current data revision? |
| Report release | What report state was recorded after readiness checks? |

## Choose a journey

1. [Plan an experiment](first-experiment/) — orient yourself, define the question, and complete intended use and provenance.
2. [Preserve methods and record runs](methods-and-runs/) — revise procedures safely, assess validation, and record executions.
3. [Record measurements and analyse](measurements-and-analysis/) — capture provenance-rich observations and save reproducible calculations.
4. [Write, review, and release](review-and-release/) — separate conclusions, scientific review, and report status.
5. [Correct records and inspect history](corrections-and-history/) — preserve prior values and compare retained versions.
6. [Back up and restore](backup-and-restore/) — choose between JSON exchange and a complete browser archive.
